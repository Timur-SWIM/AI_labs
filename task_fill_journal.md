# 1. Что считать источником истины

При заполнении журнала использовать данные в следующем приоритете:

1. `results/*.json`, `results/*.csv` — фактические результаты экспериментов.
2. `plots/*.png` — фактически построенные графики.
3. `report/report.md` — текст отчёта, выводы и интерпретация.
4. `report/theory.md` — теоретические ответы.
5. `report/answers.md` — ответы на контрольные вопросы.
6. Исходный код лабораторной — для проверки формул, архитектур и параметров.
7. `task_labXX.md` — **только требования**, но не источник экспериментальных результатов.

Нельзя:
- придумывать значения метрик;
- вручную подставлять «красивые» результаты;
- выдавать synthetic/smoke-test данные за результаты варианта;
- заполнять отсутствующие результаты догадками.

Если нужного результата нет:
1. проверить, есть ли `run_all.py`;
2. если есть — запустить лабораторную;
3. повторно проверить `results/` и `plots/`;
4. если данных всё ещё нет — оставить поле незаполненным и записать причину в `journal_fill/unfilled_fields.md`.

# 10. Правила заполнения текста

Основной инструмент:

```python
page.insert_textbox(...)
```

или эквивалент PyMuPDF.

## Шрифты

Для кириллицы использовать установленный системный шрифт, например:

```text
/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf
/usr/share/fonts/truetype/dejavu/DejaVuSans-Bold.ttf
```

Перед применением проверить путь:

```bash
fc-match "DejaVu Sans"
fc-match "Liberation Sans"
```

Не использовать шрифт, если кириллица отображается квадратами.

## Размер

Ориентиры:
- основной заполняемый текст: 8–10 pt;
- плотные таблицы: 7–8 pt;
- подписи графиков: 7–9 pt.

Нельзя уменьшать основной текст ниже 6.5 pt только ради помещения в поле.

Если текст не помещается:
1. сократить формулировку без потери смысла;
2. убрать повторения;
3. использовать перенос строк;
4. только затем немного уменьшить размер.

Не писать поверх печатного текста журнала.

Не закрывать:
- заголовки;
- рамки таблиц;
- номера страниц;
- подписи полей;
- формулы из методички.

# 11. Правила заполнения таблиц

Для каждого табличного поля:

1. Определить геометрию строк/столбцов по рендеру.
2. Вставлять значения в существующие ячейки.
3. Не рисовать новую таблицу поверх существующей без необходимости.
4. Форматировать числа единообразно.

Предпочтительно:
- 3–4 значащих цифры;
- decimal point/decimal comma выбрать по стилю журнала;
- метрики не округлять так, чтобы изменился вывод.

Пример:

```text
R² = 0.954
RMSE = 0.628
```

а не:

```text
R² = 1
RMSE = 0.6
```

если исходные результаты точнее.

Сохранять aspect ratio.

Если место узкое:

```text
journal_fill/collected_results.json
```

Пример:

```json
{
  "lab04": {
    "xor": {
      "architecture": "2-4-1",
      "accuracy": 1.0,
      "solver": "Adam",
      "training_curve": "lab04/plots/xor_training_curve.png"

  }
}
```

Значения должны извлекаться из реальных результатов, а не быть захардкожены в скрипте.
